# Executive Summary

## O que é

Lib Python que recebe um arquivo de áudio (`.mp3`/`.wav`/etc.) e produz um documento ChordPro (`.chordpro`) com:
- Acordes posicionados na sílaba correta da letra (idealmente a tônica)
- Notação rítmica para passagens instrumentais (`[E]x///`)
- Outputs alternativos por output profile (5 profiles plugáveis)

## Decisões macro

| Decisão | Valor | Por quê |
|---|---|---|
| **Plataforma do MVP** | Mac-first | Mac é daily driver + sempre ligado; case studies mostram retrofit Apple Silicon custa 3-10× vs day-1 abstraction custa 1.3-1.5× |
| **Chord engine v0.1** | Chordino via `chord-extractor` | Battle-tested, instala fácil, vocab limitado mas funciona em ambas plataformas; BTC-ISMIR19 fork em v0.2 com harness de validação pronto |
| **Default output profile** | `inline_slash` | Compat com OnSong, ProPresenter, SongbookPro, iasdermelinda real-world; `chordpro_ref` opt-in para canonical strict |
| **Validação estatística** | 3 tiers (CI 6 / nightly 30 / pre-release 147) | Owner é dono do banco do site iasdermelinda → export SQL → JSON checked-in; ground truth grátis |
| **Test corpus PT-BR** | 6 worship songs do iasdermelinda.com.br | Format ChordPro nativo, slash chords, time signature ambíguo (Grande Deus 6/8 vs 4/4), modulação |
| **EN coverage** | 1-3 songs decidir na semana 6 | Few enough, owner valida pessoalmente |
| **Render headless HTML** | Sibling project (`titan-chordpro-render` em TS/JS) | Não em v0.1; bridge via `model_dump_json()` |
| **Phase-2 schemas** | `Correction` + `CorrectionLog` em v0.1 (não consumidos) | Reservar ponto de extensão para editor app + LearnableEngine futuro |

## Estimativa

10 semanas de trabalho focado. Como side-project, calendário real ~3-5 meses.

# Section 1 — Architecture overview + Module structure

## Visão geral conceitual

A lib é uma **pipeline determinística** que recebe um arquivo de áudio e produz um documento ChordPro. Cinco estágios + um orquestrador + um writer:

```
                    ┌─────────────────────────────────────────────────┐
                    │           titan_chordpro.transcribe()            │
                    │              (orchestrator)                      │
                    └────────────────────┬────────────────────────────┘
                                         │
              ┌──────────┬──────────┬────┴─────┬──────────┐
              ▼          ▼          ▼          ▼          ▼
        ┌─────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌──────────┐
        │  Sep    │ │ Trans  │ │ Beat   │ │ Chord  │ │ Lang     │
        │ (stems) │ │ (words)│ │ (grid) │ │ (chords)│ │(syllab.)│
        └─────────┘ └────────┘ └────────┘ └────────┘ └──────────┘
              │          │          │          │          │
              └──────────┴──────────┴──────────┴──────────┘
                                         │
                                         ▼
                                ┌──────────────────┐
                                │  Fusion Engine   │  ← IP central da lib
                                │ (place chord on  │
                                │   syllable)      │
                                └────────┬─────────┘
                                         │
                                         ▼
                              ┌────────────────────┐
                              │ ChordPro Writer    │
                              │ (output profiles)  │
                              └────────────────────┘
                                         │
                                         ▼
                                  song.chordpro
```

## Princípios arquiteturais

1. **Engines são plugáveis via Protocol** — orquestrador depende só de interfaces, nunca de implementações concretas.
2. **Pure-Python core** — Fusion Engine, Writer, Schemas, CLI rodam sem qualquer ML. Testáveis com mocks.
3. **ML é encapsulado nos Engines** — modelos rodam dentro de implementações concretas (`whisper_cpp`, `chordino`, etc.); fusion/writer/schemas não importam torch/whisper diretamente. **Isso não restringe o uso de ML — pelo contrário, habilita evolução**: trocar modelos por melhores sem refactor, plugar Engines "learnable" (que aplicam correções salvas) na phase 2, fine-tuning futuro.
4. **Provenance everywhere** — cada output do pipeline carrega confidence + version + engine name. Auditável end-to-end.
5. **Fail-fast com exception específica** — `TranscriptionError`, `ChordRecognitionError`, etc. Cada erro carrega contexto debugável.
6. **Idempotência e cacheability** — separation/transcription/etc são caros; cada engine pode opcionalmente cachear outputs em `.titan-cache/<sha256-do-audio>/<stage>.json`.
7. **Outputs editáveis + audit trail para aprendizado** — `ChordProDocument` é Pydantic mutable; cada chord/word/syllable event carrega `confidence` + `source_engine`. Apps downstream (editor visual phase 2) podem aplicar correções e re-emitir ChordPro. Schema `CorrectionLog` (definido em v0.1 mas não consumido) reserva ponto de extensão para `Learnable*Engine`s na phase 2.

Esta lib é o **núcleo Python** do ecossistema Titan ChordPro. Sibling projects planejados (NOT em v0.1) usarão `ChordProDocument.model_dump_json()` como API de integração:

```
    │ ChordProDocument JSON (Pydantic serialization)
```

**Por que TypeScript/JS para o renderer:** HTML/DOM/CSS é domínio JS. Forçar Python a emitir HTML semântico viola fit-de-linguagem.

**Bridge é grátis:** `model_dump_json()` já serializa toda a estrutura.

**Implicação para esta lib:** ZERO mudança de escopo em v0.1.

# Section 2 — Engine Protocols + Schemas

## Por que Pydantic v2

Toda comunicação inter-módulo passa por modelos Pydantic v2:

1. **Validação automática** — `timestamp.end > timestamp.start`, `confidence ∈ [0,1]`, etc., garantidos no momento de construção.
2. **JSON nativo** — `.model_dump_json()` / `.model_validate_json()` sem boilerplate.
3. **FastAPI / web frontend ready** — phase 2 (editor) provavelmente terá camada web.
4. **Imutabilidade opcional** — `model_config = ConfigDict(frozen=True)` para shapes que não devem mutar (Provenance, EngineInfo, EngineRegistry).
5. **Discriminated unions** — para `LyricLine | InstrumentalLine`.

## Core Data Schemas

Definidos em `core/schemas.py`:

### Time and confidence primitives

```python
from pydantic import BaseModel, Field, field_validator, model_validator, ConfigDict
from typing import Annotated, Literal, Self
from datetime import datetime
from pathlib import Path

class TimeStamp(BaseModel):
    """Time interval in seconds from start of audio."""
    start: float = Field(ge=0)
    end: float = Field(ge=0)
    
    @field_validator('end')
    @classmethod
    def end_after_start(cls, v: float, info) -> float:
        if 'start' in info.data and v < info.data['start']:
            raise ValueError('end must be >= start')
        return v
    
    @property
    def duration(self) -> float:
        return self.end - self.start

Confidence = Annotated[float, Field(ge=0.0, le=1.0)]
```

### Event types

```python
class WordEvent(BaseModel):
    text: str
    timestamp: TimeStamp
    confidence: Confidence = 1.0
    source_engine: str
    language: str | None = None  # ISO 639-1

class PhonemeEvent(BaseModel):
    symbol: str  # IPA or ARPABET
    timestamp: TimeStamp
    parent_word_idx: int = Field(ge=0)
    confidence: Confidence = 1.0

class SyllableEvent(BaseModel):
    """A syllable derived from phonemes via Maximum Onset Principle, or from
    orthography when phonemes are unavailable."""
    text: str  # orthographic form, e.g. "hel" of "hello"
    phoneme_indices: list[int] = []  # indices into the phoneme list
    timestamp: TimeStamp
    is_stressed: bool
    parent_word_idx: int = Field(ge=0)
    confidence: Confidence = 1.0

class ChordEvent(BaseModel):
    """A detected chord with optional bass note for slash-chord support.
    
    `bass_note` may be supplied independently when the engine extracted bass
    from the bass stem (e.g. Chordino). When `symbol` already encodes a slash
    chord (e.g. "C/E"), `bass_note` MUST agree or be None — enforced by validator."""
    
    symbol: str
    timestamp: TimeStamp
    bass_note: str | None = None
    confidence: Confidence = 1.0
    source_engine: str
    
    @model_validator(mode='after')
    def validate_bass_consistency(self) -> Self:
        if '/' in self.symbol and self.bass_note is not None:
            symbol_bass = self.symbol.rsplit('/', 1)[1].strip()
            if symbol_bass != self.bass_note:
                raise ValueError(
                    f"chord symbol bass {symbol_bass!r} disagrees with "
                    f"bass_note field {self.bass_note!r}"
                )
        return self
    
    @property
    def is_slash(self) -> bool:
        return '/' in self.symbol or self.bass_note is not None
    
    @property
    def effective_bass(self) -> str | None:
        if self.bass_note:
            return self.bass_note
        if '/' in self.symbol:
            return self.symbol.rsplit('/', 1)[1].strip()
        return None
```

### Beat grid

```python
class BeatGrid(BaseModel):
    beats: list[float]  # seconds, monotonically increasing
    downbeat_indices: list[int]
    bpm: float = Field(gt=0)
    bpm_variable: bool = False
    meter: tuple[int, int] = (4, 4)
    confidence: Confidence = 1.0
    source_engine: str
    
    @field_validator('beats')
    @classmethod
    def beats_monotonic(cls, v: list[float]) -> list[float]:
        if any(v[i] >= v[i+1] for i in range(len(v)-1)):
            raise ValueError('beats must be strictly monotonically increasing')
        return v
    
    @field_validator('meter')
    @classmethod
    def meter_valid(cls, v: tuple[int, int]) -> tuple[int, int]:
        if v[0] <= 0 or v[1] not in {2, 4, 8, 16}:
            raise ValueError(f'invalid meter {v}')
        return v
```

## Document Schemas

Em `writer/document.py`:

```python
class ChordMarker(BaseModel):
    """A chord pinned to a specific character position in a rendered line."""
    chord: ChordEvent
    char_position: int = Field(ge=0)
    placement_strategy: Literal[
        'melisma_start',       # chord falls inside a detected melisma
        'stressed_syllable',   # chord on tonic syllable (best case)
        'any_syllable',        # chord on nearest syllable (good case)
        'before_word',         # chord positioned before closest word
        'beat_boundary',       # used for free-standing chords in InstrumentalLine
    ]

class LyricLine(BaseModel):
    line_type: Literal['lyric'] = 'lyric'
    text: str
    chord_markers: list[ChordMarker]
    word_alignments: list[WordEvent] = []  # for traceability / phase-2 editing
    syllable_alignments: list[SyllableEvent] = []
    confidence: Confidence = 1.0

class InstrumentalLine(BaseModel):
    line_type: Literal['instrumental'] = 'instrumental'
    chords: list[ChordEvent]
    measures: int = Field(gt=0)
    pattern_hint: Literal['full_measure', 'half_measure', 'beat'] = 'full_measure'
    label: str | None = None  # 'Intro', 'Solo', etc.
```

# Section 3 — Fusion Engine algorithm

## Por que fusion engine é o IP da lib

ML engines são **commodity** em 2026. O que diferencia Titan é o que vem depois:

1. Quantizar chord events para o beat grid dentro de tolerância perceptiva
2. Subdividir palavras em sílabas com timestamps derivados de fonemas
3. Identificar a sílaba tônica e ancorar chord markers nela
4. Fundir múltiplas evidências (chord onset + beat + bass + vocal) — v0.2
5. Detectar melismas e tratar adequadamente
6. Inferir seções (verse/chorus/instrumental) a partir de gaps na lyrics
7. Gerar notação rítmica para instrumentais (`[C]x///`, half-measures, 6/8)

Pure Python intencionalmente: **testável com fixtures determinísticos**, sem dependência de GPU.

### 3.7 `placer.py` — main algorithm

```python
def place_chords_in_line(
    line_text: str,
    words: list[WordEvent],
    syllables: list[SyllableEvent],
    chords_in_line: list[ChordEvent],
    beat_grid: BeatGrid,
    melismas: list[Melisma],
    language: str,
) -> tuple[LyricLine, list[ChordEvent]]:
    """Hierarchical fallback (5 strategies):
    1. melisma_start — chord falls inside a detected melisma
    2. stressed_syllable — chord on tonic syllable within ±150ms of fused onset
    3. any_syllable — chord on closest syllable within ±300ms
    4. before_word — chord BEFORE the closest word (within 500ms)
    5. orphaned — no syllable/word in window; returned as leftover for sectioner
       to insert as sibling InstrumentalLine
    
    Returns LyricLine + orphaned chords list."""
    
    markers = []
    orphans = []
    for chord in chords_in_line:
        t_anchor = fuse_onsets_v01(chord, beat_grid)
        
        # Step 1: melisma overlap (highest priority)
        melisma = _find_melisma_at(melismas, t_anchor)
        if melisma is not None:
            cand = syllables[melisma.syllable_idx]
            markers.append(ChordMarker(
                chord=chord,
                char_position=_char_pos_of_syllable(line_text, cand),
                placement_strategy='melisma_start',
            ))
            continue
        
        # Step 2: stressed syllable within ±150ms?
        cand = _find_stressed_syllable_within(syllables, t_anchor, 0.15)
        if cand is not None:
            markers.append(ChordMarker(
                chord=chord,
                char_position=_char_pos_of_syllable(line_text, cand),
                placement_strategy='stressed_syllable',
            ))
            continue
        
        # Step 3: any syllable within ±300ms?
        cand = _find_any_syllable_within(syllables, t_anchor, 0.30)
        if cand is not None:
            markers.append(ChordMarker(
                chord=chord,
                char_position=_char_pos_of_syllable(line_text, cand),
                placement_strategy='any_syllable',
            ))
            continue
        
        # Step 4: before closest word (within 500ms)?
        cand_word = _closest_word(words, t_anchor)
        if cand_word is not None and abs(cand_word.timestamp.start - t_anchor) < 0.50:
            markers.append(ChordMarker(
                chord=chord,
                char_position=_char_pos_of_word_start(line_text, cand_word),
                placement_strategy='before_word',
            ))
            continue
        
        # Step 5: orphan — handled by sectioner as sibling InstrumentalLine
        orphans.append(chord)
    
    line = LyricLine(
        text=line_text,
        chord_markers=markers,
        word_alignments=words,
        syllable_alignments=syllables,
        confidence=_aggregate_confidence(words, chords_in_line),
    )
    return line, orphans
```

**`'beat_boundary'` strategy:** reservada para chord events em `InstrumentalLine.chords` (posição implicitamente grid-based; não usada em LyricLine placement).

## Master pipeline

```python
def transcribe(
    audio: Path,
    language: str | None = None,
    output_profile: str = 'inline_slash',
    keep_stems: bool = False,
    cache: bool = False,
    **engine_overrides,
) -> ChordProDocument:
    audio_id = sha256(audio)
    
    # Engine selection (factory.py)
    sep_engine = factory.select_separation(**engine_overrides)
    trans_engine = factory.select_transcription(**engine_overrides)
    align_engine = factory.select_alignment(**engine_overrides)  # may be None
    chord_engine = factory.select_chord(**engine_overrides)
    beat_engine = factory.select_beat(**engine_overrides)
    
    # ML stages
    stems = sep_engine.separate(audio)
    trans_result = trans_engine.transcribe(stems.vocals, language=language)
    
    # Alignment pass (skip if transcription has phonemes)
    if trans_result.phonemes is None and align_engine is not None:
        align_result = align_engine.align(stems.vocals, trans_result.words, language)
        words, phonemes = align_result.words, align_result.phonemes
    else:
        words, phonemes = trans_result.words, trans_result.phonemes
    
    # Language-aware syllabification
    detected_lang = trans_result.detected_language or language or 'en'
    syll_engine = factory.select_syllabification(detected_lang)
    syllables = syll_engine.syllabify(words, phonemes)
    
    # Stress detection
    stress_detector = stress.detector_for(detected_lang)
    for word_idx, word_syllables in _group_by_word(syllables):
        stressed_idx = stress_detector.detect_stressed_syllable(words[word_idx], word_syllables)
        word_syllables[stressed_idx].is_stressed = True
    
    # Harmonic + beat
    harmonic_mix = _mix_for_chord(stems)
    chords = chord_engine.detect(harmonic_mix, bass_stem=stems.bass)
    beats = beat_engine.track(audio)
    
    # Fusion engine — IP central
    document = fusion.fuse(
        audio_id=audio_id, duration=stems.duration,
        words=words, phonemes=phonemes, chords=chords,
        beats=beats, syllables=syllables, language=detected_lang,
    )
    
    # Provenance
    document.provenance = _build_provenance(audio_id, sep_engine, trans_engine, ...)
    
    return document
```

## Edge cases

1. **Empty lyrics (instrumental song):** todos chords → InstrumentalLines. Section: `[intro, instrumental, outro]`.
2. **No chord detected for line:** `LyricLine.chord_markers = []` → renderer outputs plain text, sem anotação.
3. **Very fast lyrics (rap):** algorithm picks stressed_syllable first; accuracy degrades but works.
4. **Out-of-tolerance chord:** orphan flow → sibling InstrumentalLine via sectioner (não mais end-of-line).
5. **Sustain across line break:** ChordMarker fires once; next line implicitly inherits (ChordPro convention).
6. **Section boundary detection failure:** tudo vira "Verse 1"; degraded gracefully.
7. **`{c: ...}` policy:** reservado para sinal real (Solo, Modulação, Time change). Default: comentário ausente.

   | OK em v0.1 | OK em v0.2+ | NÃO emitir |
   |---|---|---|
   | `{c: Solo}`, `{c: Bridge}` | `{c: f}`, `{c: p}` (RMS) | `{c: no chord}` |
   | `{c: Modulação para G}` | `{c: cresc.}` | `{c: end of phrase}` |
   | `{c: Tempo muda para 6/8}` | `{c: Hold}` | `{c: pause}` |

```python
    'instrumental': None,
    'intro':    None,
    'outro':    None,
}

def render_section(section: Section, profile: OutputProfile) -> str:
    if section.type in ('verse', 'chorus', 'bridge'):
        start, end = SECTION_DIRECTIVES[section.type]
        body = '\n'.join(profile.render_line(line) for line in section.lines)
        return f'{start}\n{body}\n{end}\n'
    else:
        # intro/outro/pre-chorus/instrumental: prepend {c: <label>}
        comment = f'{{c: {section.label}}}'
        body = '\n'.join(profile.render_line(line) for line in section.lines)
        return f'{comment}\n{body}\n'
```

# Section 5 — Error handling + Testing strategy

## Part A — Error handling

### Filosofia: fail-fast com contexto rico

1. **Fail-fast**: stage falha → pipeline para. Sem partial outputs silenciosamente errados.
2. **Exceções específicas por stage**.
3. **Contexto debugável**: audio_id + engine + stage + raw cause.
4. **Sem retry automático**.
5. **Validação Pydantic = exception precoce**.

### Exception hierarchy

```python
class TitanError(Exception):
    """Base class for all Titan ChordPro errors."""
    
    def __init__(self, message, *, audio_id=None, stage=None, engine=None, cause=None):
        super().__init__(message)
        self.audio_id = audio_id
        self.stage = stage
        self.engine = engine
        self.cause = cause
    
    def __str__(self):
        parts = [super().__str__()]
        if self.stage: parts.append(f"stage={self.stage}")
        if self.engine: parts.append(f"engine={self.engine}")
        if self.audio_id: parts.append(f"audio_id={self.audio_id[:12]}")
        if self.cause: parts.append(f"caused_by={type(self.cause).__name__}: {self.cause}")
        return " | ".join(parts)

# Stage-specific subclasses
class SeparationError(TitanError): ...
class TranscriptionError(TitanError): ...
class AlignmentError(TitanError): ...
class ChordRecognitionError(TitanError): ...
class BeatTrackingError(TitanError): ...
class SyllabificationError(TitanError): ...
class FusionError(TitanError): ...
class WriterError(TitanError): ...

# Configuration errors
class TitanConfigError(TitanError): ...
class EngineUnavailableError(TitanConfigError): ...
```

### Failure modes — política de partial output

> **Regra:** stage produz output **válido vazio** (ex: instrumental → `words=[]`) → pipeline continua. Stage **lança exception** OU retorna **output corrompido** → fail-fast.

| Stage | Falha | Comportamento |
|---|---|---|
| Separation | Audio corrupted/unsupported | `SeparationError` (fail-fast) |
| Separation | OOM | `SeparationError` com sugestão (fail-fast) |
| Transcription | OOM | `TranscriptionError` (fail-fast) |
| Transcription | Audio puramente instrumental (`words=[]`) | Pipeline continua — output vira só `InstrumentalLine`s |
| Transcription | Whisper hallucina | VAD pre-pass detecta; se VAD falhar, output gerado com confidence baixa |
| Alignment | Modelo wav2vec2 falta | `AlignmentError` (fail-fast) |
| Chord | Audio percussivo (`chord_events=[]`) | Pipeline continua — LyricLines sem chord markers |
| Chord | Timestamps negativos | `ChordRecognitionError` (corrompido — fail-fast) |
| Beat | Audio < 5s | `BeatTrackingError` (fail-fast) |
| Beat | `beats=[]` | `BeatTrackingError` — fusion precisa de beats (fail-fast) |
| Syllabification | OOV word | Fallback CV-split + warning; pipeline continua |
| Fusion | Inputs incoerentes | `FusionError` (fail-fast — caso patológico) |
| Writer | Profile inexistente | `WriterError` (fail-fast) |

```python
def run_validation(corpus: list[dict], audio_dir: Path) -> ValidationReport:
    results = []
    for song in tqdm(corpus, desc="Validating"):
        try:
            audio = download_audio(song['youtube_id'], audio_dir)
            doc = transcribe(audio, language='pt')
            actual = doc.to_string(profile='inline_slash')
            metrics = compute_metrics(
                actual=actual,
                expected=song['chordpro_canonical'],
                song_id=song['id'],
            )
            results.append(metrics)
        except Exception as e:
            results.append(FailedMetric(song_id=song['id'], error=str(e)))
    return ValidationReport(results=results, summary=summarize(results))
```

**Validação fim Fase C:**

Phase C is gated against the iasdermelinda corpus, which is text-only ChordPro
(no labeled beat / word timestamps). Of the four metrics originally proposed,
only the two compatible with text-only ground truth are gates in Phase C:

- **WCSR-majmin ≥ 70%** — gate. Coarse interval mapping from ChordPro lyric
  positions; see benchmarks/chordpro_parser.to_intervals_labels.
- **Top 10 ≤ 3 são "Titan errado"** — manual gate (Henry classifies the
  divergence list).

The other two are reported as DIAGNOSTICS, not gates, and are deferred to
Phase D pending a labeled corpus (DALI / RWC-Pop / hand-annotated subset):

- *Beat F-measure ≥ 0.85* — Phase C computes beat consistency vs librosa
  (cross-detector sanity check; see compute_beat_consistency_vs_librosa).
  The 0.85 gate against ground truth moves to Phase D.
- *Word offset < 100ms* — Phase C reports no word offset metric (no
  reference word timestamps in the corpus). Moves to Phase D with labeled
  word boundaries.
